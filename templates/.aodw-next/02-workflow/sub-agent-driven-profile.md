# Sub-Agent-Driven 执行协议

> 版本 1.0 ｜ 由 RT-125 全程实践定稿（4 轮规划审计 + 3 轮计划审计 + 9 个执行单元）。
> 本文件每条约束都标注「谁来拦」——没有机械落点的条款不得增补进来（RT-125 决策 8）。

## 0. 适用判断

适合：多单元、改动面可切分、执行时间长到会遭遇上下文压缩/注意力稀释的 RT。
不适合：单文件小修（走轻量车道）、纯讨论/设计（走 discussion/Design）。

与 autopilot 的关系：autopilot 是**纵向切**（每轮丢上下文、从 state 重读），
本模式是**横向切**（主 Agent 只保留计划与回执摘要，脏活交执行 Agent 用完即弃）。
两者可叠加，但先用本模式——RT-125 实证它对「越执行越偏」更对症。

## 0.5 执行器无关原则（Runner-Agnostic，2026-08-16 增设）

AODW 需运行在多个执行器上（Claude Code / Codex / GLM Z Code 等），故：

> **正确性机制必须 runner-agnostic；编排机制只当加速器——可用则用，不可用不得影响流程成立。**

| 层 | 落点 | 可移植性 |
|---|---|---|
| 正确性机制 | 门禁（`rt-guard.sh` CLI + `rt-gates.yaml`）、底线阻断（pre-commit，git 层）、文件化交接（任务包/回执/复盘）、流程规则（markdown） | **必须**任何执行器可用——全部落在文件系统与 git 层 |
| 编排加速器 | Claude Code hooks 防呆层、subagent/Teams、Codex Multi Agents 等各家原生编排 | 允许绑定执行器，但失效时上表机制必须独立成立 |

本模式中的「执行 Agent」是**可替换 runner**——与业务侧章节生产的「可替换 Work Agent」
（CLAUDE.md 章节执行路径）同构。派发只依赖冻结任务包文件，不依赖任何执行器专属的
消息/编排 API。

谁来拦：计划层审计官维度 2（`04-auditors/aodw-plan-auditor-rules.md`）——
出口判据若依赖执行器专属特性且无 runner-agnostic 降级路径，按不可机械判定处理。
评估依据与触发条件存档于 `RT/_deferred-items.md` DI-005。

## 1. 角色与责任（不可转让）

| 角色 | 职责 | 禁止 |
|---|---|---|
| **主 Agent** | 亲写规划与计划；裁决审计 findings 与执行回执；派发/勾账；对最终结果负责 | 把规划或计划外包给 sub agent（丧失裁决反馈的能力） |
| **规划审计 Agent** | 独立上下文审 rt-lite/spec；只读；出 findings | 修改任何文件 |
| **计划审计 Agent** | 独立上下文审 rt-plan 的可执行性（六维度见 `04-auditors/aodw-plan-auditor-rules.md`） | 重审规划层、修改文件 |
| **执行 Agent** | 领一个冻结任务包，独立完成一个单元，交结构化回执 | 读任务包之外的对话上下文；触碰白名单外文件 |
| **复盘 Agent** | RT 关闭前独立产出 retrospective.md（契约见 `01-core/ai-knowledge-rules.md` §10） | 由主 Agent 兼任（锚定偏差） |

调研类脏活（读大量代码/历史 RT）外包给只读 agent、只回结论——这是保护主 Agent
上下文的主要手段，与规划权不外包不矛盾。

## 2. 生命周期

```
规划环（≤3 轮）→ 冻结 → 计划环（≤3 轮）→ 冻结 → 单元循环 → 收口复盘 Gate → 关闭
                                              ↑______回执触及计划→重审______|
```

### 2.1 两道审计环

- 提交 → 独立 Agent 审 → findings 回灌 → 修订 → 再审；**P0 清零才冻结**。
- **轮次上限 3**（防 Feedback Friction 打转），不收敛升级人工。谁来拦：轮次记在
  rt-plan 头部版本注释，audit 记录落 `RT/RT-XXX/audit/`，复盘 Gate 核对。
- **审计环内部任何模式下不打断用户**——findings 是带引用的代码事实，不是偏好问题。
- 审计 Agent 必须实读代码、实跑命令取证；findings 每条带 `file:line`/RT-ID/commit，
  无引用不计入。谁来拦：复盘 Gate 抽查 audit 记录。

### 2.2 主 Agent 修订后强制自检（RT-125 教训直接固化）

每次按 findings 修订后、交下一轮审计前，主 Agent 必须完成并留痕：

1. **实跑全部出口判据命令并记录返回值**——不是核对引用文本。
   （RT-125 实证：3 个 P0 里 2 个一跑 grep 就自捕；只核引用什么都查不出。）
2. **交叉引用存在性校验**：声称「§X 有某物 / 已写入 Y」的，去 X/Y 确认真有。
   （RT-125 在修复该病症的 RT 里犯了三次此病。）
3. 谁来拦：`rt-guard.sh` G110（xref 判据）+ 复盘 Gate 核对自检留痕。

### 2.3 单元循环

**单元判据**：出口可机械判定 + 改动面可事先界定。单元内可多步，不跨验收边界。

每个单元五步：
1. 主 Agent **冻结任务包** `handoff/unit-<id>-input.md`（六节：执行环境/入口判据/已定决策/
   任务/出口判据/硬约束/回执要求）并提交。**投影来源、禁投清单与冻结前校验见
   `02-workflow/task-pack-projection.md`**——任务包 §3 是出口判据正本，rt-plan 单元节
   只是草稿输入（该文件 §1 附 RT-125 四单元实证）
2. 派执行 Agent，prompt 只指向任务包（文件是唯一输入，不传对话上下文）
3. 执行 Agent 完成后交回 `handoff/unit-<id>-receipt.md`（四节，见 §3）并提交
4. **主 Agent 独立复核**——实跑出口判据，不采信回执自述（RT-125 八份回执全部独立复核（U3 由主 Agent 直接执行，无独立回执），
   两次抓到与自述的偏差）
5. 勾账进 rt-plan 进度（附 commit 与复核结论）

纯验收/基础设施动作（建 worktree、跑回放对照）可由主 Agent 直接执行，但仍须写回执。

**并行**：文件零交集的单元可并行；共享 worktree 时各自只 add 白名单路径、
遇 index.lock 等待重试、禁 `git add -A`。

### 2.4 回执触及计划的判定（默认触及，免审需举证）

| 回执条目 | 处置 |
|---|---|
| 增/删/并步骤、改验收判据、改 scope/硬约束 | **无条件重过计划审计** |
| 推翻规划层事实前提 | **退回规划环** |
| 纯事实澄清且不改后续步骤与判据 | 可免审，理由落盘 |
| 判据内的实现细节选择 | 可免审 |

谁来拦：rt-plan 版本号必须递增且有对应 audit 记录（或人工批准的替代验证留痕）；
复盘 Gate 核对版本链。

### 2.5 确认粒度（模式内再分两档）

- **全自动**：零确认；熔断才上报（轮次上限、无安全默认的二选一、连续无进展）。
- **人工确认**：仅在**每个执行单元回执交回后**停一次 + 合并前确认。
  审计环内部两档都不打断。

## 3. 回执契约（谁来拦：任务包侧由 G112/G113 拦；回执侧暂无机械落点，由主 Agent 人工复核）

四节缺一不可：

```
① 改了什么 —— 逐文件 + commit hash
② 出口判据验证 —— 逐条期望 vs 实测，附实际命令与原始输出
③ ⚠️ 与计划不符 / 计划未覆盖之处 —— 即使为零也显式写「无」
④ 判断 —— 下游能否接手、有无阻塞
```

③ 是整个模式的心脏：RT-125 八份回执的 ③ 节抓到了七轮纸面审计全部漏掉的问题
（worktree 忽略规则不分发、spike 示例正则防不住自己发现的漏洞、exec 位缺失、
七个存量 meta 语法坏）。**「允许反馈」等于没有反馈，必须强制成节。**

```

  rt-lite.md           # 规划正本（Spec-Lite 模板 §1-§7 + 硬约束节）

```

## 5. 熔断参数

| 参数 | 值 | 依据 |
|---|---|---|
| 审计环轮次上限 | 3 | RT-125 规划环第 3 轮触发，实证有效 |
| 升级动作 | 停止迭代、向人工陈述分歧与选项 | 不得静默突破上限 |
| 突破上限 | 仅人工显式批准，且批准本身落盘 | RT-125 有先例（v3 后人工批准改自举验证） |
